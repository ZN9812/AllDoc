# AI 연결

AI는 문서를 마음대로 고치지 않습니다. AI의 답은 **제안 목록**으로 "변경 내역"에 올라가고, 사용자가 **적용한 것만** 문서에 반영됩니다.
서버는 AI가 돌려준 제안을 **문서와 대조**해서, 문서에 없는 문단·글을 가리키는 제안은 버리고 알려 줍니다(예: "문서와 맞지 않는 제안 2개는 제외했어요").

## 무엇이 AI 서비스로 가나요

AI 대화나 "내 규칙" 점검을 쓸 때만, 브라우저가 서버로 다음을 보냅니다. 서버는 이것을 AI 서비스(기본 Claude)로 전달합니다.

- 문서의 **문단 글**과 문단별 서식 요약(글꼴, 크기, 굵기, 정렬, 줄 간격). 한글·Word 문서는 표 칸 안의 글도 문단으로 보내고, 어느 표의 몇 행 몇 열인지("표 2 · 3행 1열")를 함께 보냅니다. 머리말·꼬리말·각주·미주·글상자 안의 글도 문단으로 보내며 "머리말", "꼬리말(홀수 쪽)", "각주 3", "글상자 2" 같은 위치를 함께 보냅니다. 파일 자체는 보내지 않습니다.
- 사용자가 시킨 말, 최근 대화 10개, "내 규칙"에 적은 글 또는 기준 문서에서 뽑은 서식 요약
- 한 번에 보낼 수 있는 문서 글자 수는 120,000자(`MAX_DOC_CHARS`)까지입니다. 넘으면 나누어 달라고 안내합니다.

"문서 안 일관성"과 "기준 문서" 점검은 **AI를 쓰지 않고** 브라우저 안에서 계산하며, 로그인도 필요 없습니다.
처음 AI를 쓸 때 "문서 내용이 AI 서비스로 전송됩니다" 안내와 동의를 받고, 설정에서 AI 기능을 끄거나 동의를 철회할 수 있습니다.
서버는 문서를 저장하지 않습니다. 정상 처리 기록에는 요청의 종류·글자 수·제안 개수·걸린 시간만 남기고 문서 글은 남기지 않습니다.
실패했을 때는 AI 서비스가 돌려준 오류 문장(최대 500자)이 서버 기록에 남습니다. 서비스가 그 문장에 요청 내용을 담는지는 확인하지 못했으니, 기록을 외부에 공유할 때는 훑어 보세요.

## 설정

환경 변수(`.env`):

| 이름 | 뜻 |
| --- | --- |
| `AI_PROVIDER` | `anthropic`(Claude, 기본), `mock`(데모), `off`(AI 끔) |
| `ANTHROPIC_API_KEY` | Claude API 키. **서버에만** 둡니다. 브라우저로는 절대 내려가지 않습니다. |
| `AI_CONFIG_PATH` | 작업별 설정 파일(JSON)의 경로. 없으면 아래 기본값을 씁니다. |
| `DAILY_AI_LIMIT` | 사용자 1명이 하루에 쓸 수 있는 AI 요청 수(기본 5) |
| `APP_TIMEZONE` | 하루가 바뀌는 기준 시간대(기본 `Asia/Seoul`) |

기본 모델은 `claude-opus-5-5`, 추론 강도(`effort`)는 `medium`, 최대 응답 길이는 16,000 토큰입니다.

### 작업별 설정 파일

AI 작업은 두 가지입니다. **`chat`**(AI 대화 탭)과 **`format_check`**(서식 점검의 "내 규칙"). 작업마다 모델·시스템 프롬프트·주소를 다르게 줄 수 있습니다.

```json
{
  "default": { "model": "claude-opus-5-5", "effort": "medium" },
  "tasks": {
    "chat":         { "systemPromptAppend": "문장은 공문서 말투(~합니다)로 고칩니다." },
    "format_check": { "model": "my-finetuned-model", "apiKeyEnv": "MY_MODEL_API_KEY", "baseURL": "https://llm.example.com" }
  }
}
```

`default`는 두 작업에 공통으로 적용되고, `tasks.<작업>`이 그 위에 덮어씁니다. 모르는 항목이 있으면 서버를 켤 때 바로 오류로 알려 줍니다.

| 항목 | 뜻 |
| --- | --- |
| `provider` | 이 작업을 처리할 연결부(`anthropic`, `mock`, `off`) |
| `model` | 모델 이름. 파인튜닝한 모델 이름도 여기에 적습니다. |
| `effort` | `low` `medium` `high` `xhigh` `max` |
| `maxTokens` | 응답 최대 토큰(256~20,000) |
| `baseURL` | Claude 호환 주소를 따로 쓸 때(예: 사내 게이트웨이) |
| `apiKeyEnv` | 이 작업이 쓸 API 키가 들어 있는 **환경 변수의 이름**. 키 값 자체를 파일에 적지 않습니다. |
| `systemPrompt` / `systemPromptFile` | 기본 시스템 프롬프트를 통째로 바꿉니다(파일은 설정 파일 기준 상대 경로). 둘 중 하나만. |
| `systemPromptAppend` | 기본 시스템 프롬프트 뒤에 규칙을 덧붙입니다. |
| `fallbacks` | `default`(기본) 또는 `off`. 아래 "대체 모델" 참고 |

기본 시스템 프롬프트는 `server/src/ai/prompt.ts`에 있습니다. 통째로 바꾸면 "문서에 없는 문단을 가리키지 말 것", "제안은 지정한 형식으로만 돌려줄 것" 같은 기본 규칙도 직접 책임져야 하므로, 보통은 `systemPromptAppend`로 덧붙이는 편이 안전합니다.

### 제안의 한계

- 제안 하나에 담을 수 있는 변경은 **60개**까지입니다(`MAX_OPS_PER_PROPOSAL`). 넘는 제안은 버려집니다.
- 한 번에 올라가는 제안은 30개까지입니다(`MAX_PROPOSALS`).
- 한글·Word 문서에서는 줄바꿈이 들어간 글 고치기를 아직 적용하지 못합니다(그 제안은 "적용할 수 없어요"로 표시됩니다).

## 다른 AI(Gemini 등)를 붙이는 방법

연결부는 `server/src/ai/types.ts`의 `AiProvider` 약속만 지키면 됩니다.

```ts
interface AiProvider {
  readonly id: string;
  readonly demo: boolean;                         // 예시 응답이면 true (화면에 "데모" 안내가 뜹니다)
  propose(input: { request: AiRequest; signal?: AbortSignal }): Promise<{ reply: string; proposals: RawProposal[] }>;
}
```

1. `server/src/ai/gemini.ts` 같은 파일을 만들어 `AiProvider`를 구현합니다. 요청(`AiRequest`)을 모델에 맞는 메시지로 바꾸고,
   응답을 `server/src/ai/schema.ts`의 `AiOutputSchema` 모양(`reply`, `proposals`)으로 돌려줍니다. 메시지를 만드는 `buildMessages`(`prompt.ts`)는 그대로 쓸 수 있습니다.
2. 실패는 `ProviderFailedError`(연결·한도·응답 이해 실패: 사용 횟수를 돌려줍니다)나 `ProviderRefusedError`(모델이 답을 거절: 횟수를 돌려주지 않습니다)로 던집니다.
   사용자에게 보일 문장은 한국어로 쉽게 쓰고, 원문 오류는 `cause`에 담으면 서버 기록에만 남습니다.
3. `server/src/config.ts`의 `PROVIDER_IDS`에 이름을 추가하고, `server/src/ai/providers.ts`의 `createProviders`에서 그 이름일 때 만들어 끼웁니다.
4. 설정 파일에서 작업별로 고릅니다: `{ "tasks": { "format_check": { "provider": "gemini", "model": "…" } } }`.
5. 시험은 `server/src/ai/anthropic.test.ts`를 본떠, 가짜 클라이언트로 성공·거절·실패 경로를 확인하세요.

화면과 문서 편집기는 어느 AI를 쓰는지 모르게 만들어져 있어, 서버 쪽만 바꾸면 됩니다.

## 사용 횟수와 비용

- 비용은 **운영자가 부담**합니다(사용자 API 키를 받지 않습니다). Anthropic 콘솔에서 월 지출 한도도 함께 걸어 두세요.
- 하루 한도는 사용자별(`DAILY_AI_LIMIT`)이고, 날짜는 `APP_TIMEZONE` 자정에 바뀝니다. 횟수는 서버의 SQLite(`DATA_DIR`)에 사용자 번호와 함께 저장됩니다.
- 요청을 보내기 **전에** 횟수를 하나 쓰고, 연결·응답 실패면 돌려줍니다. 모델이 정책상 거절한 경우는 돌려주지 않습니다.
- 같은 사용자의 요청은 한 번에 하나만 처리합니다(진행 중 요청이 있으면 "이전 요청을 처리하는 중"이라고 안내).
- 로그인 없이 쓰는 `AUTH_MODE=none`은 한도가 없습니다. 사내망 같은 믿을 수 있는 곳에서만 쓰세요.

## 대체 모델(`fallbacks`) — 기본으로 켜져 있어요

Claude는 정책상 답을 거절할 때가 있습니다. 이때 서버 쪽에서 대체 모델로 한 번 더 시도하게 하는 Anthropic 베타 기능(`server-side-fallback-2026-07-01`)을 기본으로 요청에 붙입니다(`fallbacks: "default"`).

- 서비스가 이 옵션을 받아들이지 않으면(400 오류) 서버가 **옵션 없이 한 번 다시 시도**하고, 서버 기록에 경고를 남깁니다.
- 대체 모델이 답하면 비용·응답 품질이 달라질 수 있습니다. 쓰지 않으려면 설정 파일에서 `"fallbacks": "off"`로 끄세요.
- **이 코드는 실제 API 키 없이 개발해서, 진짜 Claude 호출은 아직 시험하지 못했습니다.** 자동 시험은 가짜 클라이언트로 요청 모양과 오류 처리만 확인합니다.
  운영 전에 실제 키로 "AI 대화"와 "내 규칙"을 한 번씩 돌려 보고, 서버 기록에 경고가 없는지 확인하세요.

## 데모(`mock`)

`AI_PROVIDER=mock`이면 실제 AI 없이 정해 둔 규칙으로 제안을 만듭니다. 화면 흐름(제안 → 적용·취소·되돌리기)을 API 키 없이 확인하려는 용도이고 AI의 품질을 대신하지 않습니다.
알려진 오탈자(몇일→며칠, 할려고→하려고 등)를 고치고, "내 규칙"에서는 글에 적힌 글꼴·크기(`11pt`)·줄 간격(`줄 간격 160%`)을 읽어 맞춥니다. 응답에는 "(데모)" 표시가 붙습니다.
